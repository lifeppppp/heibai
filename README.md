# 文字击穿 · 长征运输队

**故事**：暑假做长征报告的主角，翻太爷爷的文章时穿了进去，变成文章里的一个字。那篇文章写的是长征中**文件运输队**的经历。

**结构**：四幕（0 / 1 / 2 / 3）。现在做的是 **第一章第一幕**；第零章先不做，但代码结构按"前面还有一章"来留口子。

**画面**：屏幕上下分栏。**上方**是书里的文字（黑底白字），**下方**是文字对应的画面（黑白，主要构成元素也是文字）。三维部分等指令，暂不建模；红色等指令，暂不加入。

---

## 第一章第一幕（已实现）

分镜：

1. 屏幕上方、水平居中，**逐字打出**：「谨以此作，纪念长征中运输队的同志」——0.16 秒/字，**打到逗号处停 1 秒**再继续；全句打完后**停 3 秒**
2. 「我」从屏幕上方落下，**击穿**这行字——**这行字不消失**，只被撞得**稍微散开**（略往下沉）
3. 散开的字像**浮上水面**一样，沿阻尼弹簧慢慢浮到屏幕上六分之一处，成为上下两半的隔断
4. 「我」减速，**停在屏幕正中**
5. 「我」**停稳后再静置 2 秒**，然后「我」的上下才慢慢浮出**一列名字**（暂用「无名氏」占位），**出现顺序：先「我」上方最近的一个、再下方最近的一个，其余随机；间隔完全一致**，列顶不越过那行字

**视觉规则（按反馈定下）**：所有字都是**纯白、不发光**；「我」与名字**同字号、同明暗**——它是队列里的一个，不是主角特写。

6. 名字全部出现后，两侧**用符号画出道路**（`| / \ { } * + ：`），从最底部向上铺，与人名等长、不遮挡
7. 道路铺到尽头后**视角拉远**：整体（含「我」与道路）不断缩小到约原来的 **1/10**，缩出来的空位里补出更多「无名氏」，道路随之延长
8. 拉远的同时，**屏幕两侧出现像素风的山**（纯色块、有亮面/暗面/雪冠三层明暗）；
   山和名字**过同一个镜头**——位置和大小都乘同一个 `zoom`，所以山缩小的速度和字完全一致，
   整幅画读起来是"镜头在往后退"，而不是"字在缩、山在旁边自己滑"。
   每座山单独生成：峰位、山形、雪线、岩块都不一样；
   一共 **12 座**（每侧 6 座），分**远/中/近三层**：远层先画、被中景挡掉山脚，中景又被最近那层挡住，
   所以山脚不会"浮"在空中，是一层压一层的真实山峦。三层合起来把**道路两旁的空白**填满
9. 镜头是**缓入缓出**的：起步和收势都慢，中段稳，9 秒拉远不会像被猛推一下
实测数据（1280×800）：那行字从 0.235H 浮到 1/6H（117.5px），「我」停在 400px（正中），名字 13 个、上下分布在 181~626px 之间，字号「我」与名字同为 18px。

### 山是怎么画的（改的时候别破坏这几条）

- **同一套镜头**：屏幕位置 = `中心 + 世界坐标 × zoom`，屏幕大小 = `世界大小 × zoom`。
  山因此和名字**同速**缩小；若给山单独写一套缩放，就会立刻露馅（这正是更早一版的问题）。
- **精灵图 + 连续缩放（别取整！）**：每座山先画成一张「1 像素 = 1 格」的小画布，
  再用 `drawImage` 按连续的 `zoom` 放大（`imageSmoothingEnabled = false` 保住硬边）。
  **不要**把方块边长 `round()` 成整数——那样整座山会隔几帧跳一下，看着一卡一卡。
  回归里有一条专门验这个：连采 12 帧，每帧的山宽都必须不同、单帧变化要小。
- **按"终点位置"倒推**：`ACT1.mountainSpots` 里每项写的是**拉远结束时**这座山该在哪——
  `dx`（内边离中心占半屏宽的比例）、`y`（山脚占画面高的比例）、`block`（方块像素）、`peak`（峰高块数）。
  代码把它除以 `zoomEnd` 得到世界坐标，镜头一退，山就正好落在那儿。想调整画面疏密，**改这张表就行**。
- **分三层摆，允许层间遮挡**：`mountainSpots` 里每项带 `depth`（0 近 / 1 中 / 2 远）。
  **同一层内**用游标排开、留 `mountainGapRatio` 的缝；**不同层故意重叠**。
  画的时候先按 `depth` 从大到小排（远的先画），近的才能盖住远的山脚。
  回归里验四条：12 座都在、三层、画序由远到近、至少有 2 座真被挡住。
- **现状（1280×800 实测）**：12 座、方块 3.9~10.4px、山脚跨度 288px、山顶跨度 177px、7 座被遮。
- **三层明暗，不用透明度**：亮面 / 暗面（按坡的朝向分）+ 雪冠，再加山脚压深和零散岩块。
  所有颜色都是不透明纯色，越靠下越暗；**不要用 globalAlpha 做"远景感"**，那会让山变成半透明色块。
- **每座山独立生成，而且不能太尖**：固定种子的伪随机（`seededRandom`），脊线由 1~2 个峰的折线决定；
  峰顶留一段**平台**（`f1` ≈ 0.08~0.14 山宽），之后还有一道**削尖刺**的处理：一列比左右高两格以上就压低。
  改完刷新页面山形不变，但每座都不一样。
- **尺寸跟屏幕走**：`mountainPx = clamp(min(宽,高) × mountainWorldPxRatio, 20, 72)`，
  竖屏/小窗口不会出现"山比屏幕还宽"。

1. 双击 **`START-GAME.bat`**
2. **点一下画面**（浏览器要求先交互才准放音乐，右上角徽标会变成「♪ 播放中」）
3. 想调手感就按 **`` ` ``**（Esc 下面那个键）打开调参面板

**改文字** → 打开 `content.js`（只改这一个文件，改完刷新页面）。

## 怎么玩

双击 `START-GAME.bat`（或直接双击 `index.html`）。

| 操作 | 作用 |
|---|---|
| 点击 / 空格 | 开始游戏（第一次交互同时开始放音乐） |
| 在画面里点击 | 一个字从天而降，砸在那个位置，炸开周围的字 |
| `R` | 重播开场序列 |
| `M` | 静音 / 取消静音 |

## 改内容：只改 `content.js`

所有文字和配乐都在 **`content.js`** 里，它只有内容、没有逻辑。改完存盘刷新页面即可，`game.js` 一行都不用动。

```js
const CONTENT = {
  title: '文字击穿',
  subtitle: '点击开始',
  line: '深度求索',        // 那一排字
  hero: '击',              // 从天上砸下来的字
  ambient: '求索者不畏路远星光不负赶路人夜以继日',   // 周围浮现的字
  musicTracks: ['audio/bgm.mp3'],
  musicVolume: 0.45,
}
```

⚠ **这个文件必须存成 UTF-8**（记事本另存为时编码选 UTF-8），否则中文会变乱码。

## 换成你自己的音乐（支持多首）

1. 把音乐文件（**MP3 最稳**，OGG 也行）丢进 `audio/` 文件夹。
2. 在 `content.js` 的 `musicTracks` 里按播放顺序写上它们：

```js
musicTracks: ['audio/bgm.mp3'],            // 只有一首 → 无限循环
musicTracks: ['audio/ch1.mp3', 'audio/ch2.mp3', 'audio/ch3.mp3'],  // 多首 → 播完自动接下一首，末尾回到第一首
```

多首时右上角徽标会显示 `♪ 播放中 (2/3)`，方便你确认接的是哪一首。把某一首删掉后记得同步删掉数组里那行，否则会显示「音轨缺失」——**这只是提示，游戏不会崩**。

**关于"同一文件夹、换电脑不失效"**：音轨用的是相对路径，没有任何绝对路径、没有网络请求。整个文件夹压缩成 zip、在另一台电脑解压到任意位置，路径依然成立。

## 用代码驱动一段演出（后续章节用这个）

演出内容不再写死在配置里，可以随时换：

```js
// 换一行字 + 换坠字 + 换环境字，演完回调
__game.startIntro({
  line: '天地玄黄',          // 那一行整齐排列的字
  hero: '破',                // 从天而降、击穿这行的字
  ambient: '风雨如晦鸡鸣不已', // 周围浮现的字
  onDone() { console.log('这段演完了') },
})
```

不传参数就沿用 `CFG` 里的默认值（`startGame()` 就是不带参数调用）。

`window.__game` 上现在有这些可调用/可读的东西：

| 名字 | 用途 |
|---|---|
| `startIntro(opts)` | 演一段击穿序列，`opts` 见上 |
| `startGame()` | 标题页 → 开场 → 玩法（按 `CFG` 默认内容） |
| `spawnFaller(x, y)` | 在指定位置砸下一个字 |
| `layout()` | 按当前画布尺寸重排（改完尺寸后调） |
| `S` | 运行时状态：`S.mode` / `S.phase` / `S.line` / `S.field` / `S.heroY` … |
| `CFG` | 所有可调参数，控制台里直接改，下一帧生效 |
| `fadeTo(目标, 时长秒, 回调)` | 过场黑幕：`fadeTo(1, 0.6)` 淡出到黑，`fadeTo(0, 0.6)` 淡回画面 |
| `clearStage()` | 清场：把台上的字全部收掉（换场前用） |
| `time()` | 音频时钟（秒）。做音画同步用这个，别用 `performance.now()` |
| `audio()` | 当前音轨状态：`{src, index, paused, muted, broken}` |

已验证：`startIntro({line:'天地玄黄', hero:'破', ambient:'…', onDone})` 会换掉那行字与坠字、跑完整序列，`onDone` **只触发一次**，坠字最终仍精确停在中心。

## 调参面板（按 ` 键开关）

游戏里按 **`` ` ``（Esc 下面那个键）**打开一个面板，直接拖滑块看效果，不用改代码：

| 滑块 | 管什么 |

| 落定急刹 | 坠字最后收住的那一下（越小越急） |
| 定格帧 | 撞击瞬间的停顿，打击感主要靠它 |
| 音量 | 实时生效 |
| 字号 / 字距 / 环境字数 | **重播后**才生效（要重新排版） |

改完点 **「复制参数」**，会得到这样的几行（只包含你改动过的项）：

```
CFG.gravity = 3600

```

把这几行发给我，我就写回 `CFG` 当默认值。剪贴板被拦时（某些 `file://` 环境）它会退化成一段可选中的文本，Ctrl+C 即可。

## 长文本怎么排（不用你管，但知道边界）

那行字**任意长度都不会溢出屏幕**。规则是按顺序尝试：

1. 先按 `lineSize`（默认 72）排一行；
2. 一行放不下就缩字号（逐字实测宽度、把字距算进去），缩到 **20px** 为下限；
3. 20px 还放不下就**平均拆成多行**（最多 6 行），再给每行重新定字号；
4. 多行时整体以屏幕中间为中线上下居中，坠字仍然砸在正中。

**想手动断行就直接写 `\n`**：

```js
line: '第一行\n第二行',     // 真的会排成两行，各自居中
```

空字符串、纯空格、纯换行都不会崩，只是画面上没字；emoji、中英混排、60 字超长句都测过。

实测：16 个汉字在 1280 宽下是 51px 单行；在 414 宽竖屏下自动变 2 行、每行 8 字。

调试时可以直接在地址栏指定内容预览（不用改代码）：

```
index.html?line=天地玄黄宇宙洪荒&hero=破&ambient=风雨如晦
index.html?t=1.6&line=天地玄黄          ← 再配合 t 定格到某一秒
```

## 过场怎么切（黑幕 + 清场）

现在有了“换场”的最小工具，但**什么时候用完全由你定**：

```js
__game.fadeTo(1, 0.6, () => {      // 0.6 秒淡出到全黑
  __game.clearStage()              // 收掉台上的字
  __game.startIntro({              // 铺下一幕
    line: '天地玄黄', hero: '破',
    onDone() { __game.fadeTo(0, 0.5) },   // 演完再淡回画面
  })
})
```

黑幕画在最上层，连底部提示一起盖住；`fadeTo(0.5, ...)` 这种半透状态也能停在任意不透明度。

## 高分屏 / 系统缩放

Windows 默认会把 1080p 屏设成 125% 或 150% 缩放，浏览器里对应的就是 `devicePixelRatio` = 1.25 / 1.5。这一块已实测：

| DPR | CSS 尺寸 | 画布像素 | 渲染 |
|---|---|---|---|
| 1 | 1280×800 | 1280×800 | 1:1 清晰 |
| 1.25 | 1280×800 | 1600×1000 | 1:1 清晰 |
| 1.5 | 1280×800 | 1920×1200 | 1:1 清晰 |
| 2 | 1280×800 | 2560×1600 | 1:1 清晰 |

画布像素始终 = CSS 尺寸 × DPR（上限 2 倍，避免 4K 屏上无谓地烧显卡），所以字不会糊、也不会被裁。

## 性能与耐久（实测数据）

用无头浏览器 + CPU 降速模拟不同机器，边跑边随机点击：

| 条件 | 帧率 | 堆内存 | DOM 节点 | NaN |
|---|---|---|---|---|
| 正常（连续点击 90 秒） | 60 fps | 9.5 MB 恒定 | 81 恒定 | 0 |
| CPU 降速 4 倍（老笔记本） | 60 fps | 9.5 MB | 81 | 0 |
| CPU 降速 20 倍（极端） | 10 fps | 9.5 MB | 81 | 0 |

**结论**：没有内存泄漏、没有对象堆积、没有数值发散（NaN）。

一个刻意为之的取舍：每帧时间上限被钳在 `1/30` 秒（33ms），所以**极慢的机器上演出会变成慢动作**，而不是跳过撞击帧。宁可慢，也不要漏掉“击穿”那一下。

## 出错了会怎样（不会黑屏）

演出逻辑或渲染万一抛异常，屏幕会显示：

```
演出出错了 —— 程序没崩，按 R 可以重播
<具体的错误信息>
把这个提示发给我就能定位
```

主循环不会死，音频也不会断；按 `R` 直接从干净状态重播。这是给玩家兜底的——真发到别人电脑上，宁可看到一行字也不要看到黑屏。

## 字形一致性（跨电脑会变，先知道有这回事）

游戏只用**系统字体**（`PingFang SC → Microsoft YaHei → system-ui`）。也就是说：

- Windows 上实际用的是 **Microsoft YaHei**；
- Mac 上会优先命中 **PingFang SC**；
- 装了 Noto/思源黑体的机器可能又是另一种。

同一个字在三种机器上是三种字形、宽度也略有差异。**要完全一致，只能把字体文件嵌进包里**（对中文字体得做子集化，只保留用到的字，否则一个字体就是 5–10 MB）。

想知道本机到底有哪些中文字体：按 `` ` `` 打开面板 → **「字体检查」**，会列出 `✓/✗ PingFang SC`、`✓/✗ Microsoft YaHei`…，并告诉你最靠前可用的那个。

（面板里还多了一行 **fps**，方便确认低配机器上没掉帧。）

## 挂到网页上（不需要牺牲任何功能）

这套代码 `file://` 双击和 `http://` 挂站是同一份，功能完全一致。只要守住两条：

1. **文件名全小写**（Linux 服务器大小写敏感）——目前所有文件已符合。
2. **不要用 `fetch` 读本地文件**——现在所有数据都写在 `game.js` 里，没有这个问题。

挂站时把整个 `text-impact-game` 文件夹传上去，入口是 `index.html` 即可。注意 `START-GAME.bat` 和 `README.md` 传上去没用，可以不上传。

## 这套东西的边界（重要）

- **必须整份拷贝**：`index.html` + `game.js` + `style.css` + `audio/` 四个都要走。少一个音乐就没了。
- **不要用 `fetch()` 读外部文件**：浏览器从 `file://` 打开时会拦掉这种请求。所以本项目的音乐走 `<audio src=...>`（不受此限制），数据全部写在 `game.js` 里。
- **不要改成分 ES module**（`type="module"`）：同上，`file://` 下会被 CORS 拦。现在用的是普通 `<script>`。
- **自动播放会被拦**：浏览器要求先有用户交互，所以音乐在"点击开始"时才播，这是正常的，不是 bug。
- **存档**：如果以后要存进度，`file://` 下 `localStorage` 行为不稳定。要跨机器可靠存档，就得写进游戏目录（需要本地服务）或做原生封装——到时再说，别现在踩。
- **字体**：只用了系统字体，不联网下载字体，所以离线、换电脑都不会变样。

## 想改的地方在哪

**文字和配乐 → `content.js`**（改这个就够）。
**手感参数 → 按 `` ` `` 开面板拖滑块**，或改 `game.js` 顶部 `CFG` 里的引擎参数：

| 参数 | 作用 |
|---|---|
| `gravity` | 下落有多快 |
| `scatterSpeed` | 爆炸有多猛（越远的字越接近这个速度） |
| `scatterUpBias` | 爆散时往上飘的比重 |
| `damping` | 爆散后速度衰减，越大越"短促" |
| `springK` / `springC` | 被炸开的字弹回原位的快慢与阻尼 |
| `smoothTime` | 坠字"急刹"的收敛时间 |
| `impactHold` | 碰撞定格帧时长（打击感主要靠它） |
| `musicTracks` / `musicVolume` | 配乐列表与音量 |

主体渲染在 `drawGlyph()` 一个函数里：把 `fillText` 换成 `drawImage`，物理一行都不用改。
